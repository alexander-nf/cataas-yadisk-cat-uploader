# Курсовая работа по модулю "ООП и работа с API"

## Задание

Исходное задание (https://github.com/netology-code/pyapi-diplom-basic/tree/add_cats):

1. Получить картинки кошек по API с сайта [cataas.com](https://cataas.com/) с текстом.
   Пример [api](https://cataas.com/cat/cute/says/hello) получения кошек с текстом на картинки 
2. Название папки должно совпадать с названием вашей группы в Нетологии
3. Текст картинки также должен являться названием файла на Яндекс.Диске
4. Сохранить json файл с информацией о размере файла картинки в json-файл

### Входные данные:
Пользователь вводит:
1. Текст для картинки
2. Токен с [Полигона Яндекс.Диска](https://yandex.ru/dev/disk/poligon/).
*Важно:* Токен публиковать в github не нужно!

### Выходные данные:
1. json-файл с информацией по загруженным файлам
2. Измененный Я.диск, куда добавились фотографии

### Обязательные требования к программе:
1. Использовать REST API Я.Диска и ключ, полученный с полигона.
2. Для загруженных картинок нужно создать свою папку на Я.Диске.
3. Загрузка картинок осуществляется по воздуху, т.е. локально фотографии не сохраняются. В Я.Полигоне есть необходимый метод.
4. Сделать прогресс-бар или логирование для отслеживания процесса программы.
5. Код программы должен удовлетворять PEP8.
6. У программы должен быть свой отдельный репозиторий. 
7. Все зависимости должны быть указаны в файле requiremеnts.txt.

## Решение

### Описание разработанного приложения

 Консольное приложение на Python для получения изображений котиков (с надписью / без неё) через API CatAAS и загрузки изображений на Яндекс.Диск.

Программа принимает текст, введённый пользователем, запрашивает фотографию с текстом у CATAAS, скачивает её в оперативную память, затем сохраняет на Яндекс.Диск. Далее сохраняет информацию об очередной загруженной фотографии в JSON-отчёте, хранимом на Яндекс.Диске.

### Использованные инструменты

- Среда разработки Visual Studio Code,
- Python-сервер Pylance для VS Code, 
- Линтер Ruff,
- публичный ИИ-чат [duck.ai](https://duck.ai/) (в режиме "ChatGPT Luna") для:
  - подсказок по синтаксису и примеров по некоторым структурам данных,
  - подготовки схем в разделе "Архитектура" данного README по созданному коду.
- в остальном - **продукт vibe-coding free**, текст README не проходил пост-обработку в ИИ-чате.

### Архитектура

#### Основные компоненты и зоны ответственности

| Компонент | Ответственность |
|---|---|
| `Settings` | Загрузка и хранение конфигурации |
| `Image` | Представление изображения и его метаданных |
| `CataasClient` | Получение изображений у CatAAS |
| `YaDiskClient` | Загрузка и скачивание файлов с Яндекс.Диска |
| `ReportService` | Чтение, изменение и сохранение JSON-отчёта |
| `AppService` | Пользовательский сценарий и главный цикл |
| Блок `__main__` | Инициализация приложения |

#### Сценарий работы

```text
Пользователь
    ↓
AppService
    ↓
CataasClient → CatAAS API
    ↓
Image
    ↓
YaDiskClient → Яндекс.Диск API
    ↓
ReportService → upload_report.json на Яндекс.Диске
```

### Основные возможности и механизмы (темы курса)

- Получение изображений через HTTP API.
- Добавление текста на изображения (HTTP API).
- Загрузка файлов на Яндекс.Диск (HTTP API).
- Работа с OAuth-токеном.
- Обработка HTTP-ошибок.
- Ведение (чтение/запись) JSON-отчёта.
- Использование классов и dataclass.
- Задействование "магических" (dunder) методов.
- Использование защищённых методов.
- Включение аннотаций типов.
- Логирование событий, несколько режимов детализации.
- Загрузка изображений в цикле, выход по команде пользователя.
- Изображения не сохраняются на локальный диск пользователя.

### Настройки конфигурации

Глобальные настройки программы, неизменные во время её работы:
| Переменная | Назначение |
|---|---|
| `CATAAS_API_URL` | Адрес API сервиса с изображениями котиков |
| `YA_DISK_API_URL` | Адрес API Яндекс.Диска |
| `YA_DISK_TOKEN` | OAuth-токен Яндекс.Диска |
| `NETOLOGY_GROUP_ID` | Имя или идентификатор каталога на Яндекс.Диске |
| `HTTP_TIMEOUT_SECS` | Таймаут HTTP-запросов |
| `APP_LOGGING_LEVEL` | Уровень логирования |

### Установка и запуск

#### Вариант с ручным копированием файлов

1. Создать каталог программы и открыть его в консоли.

2. Сохранить в созданный каталог файлы:
    - [requirements.txt](./requirements.txt),
    - [.env.example](./.env.example),
    - [cat_image_backup.py](./cat_image_backup.py)

Далее см. ниже пункт 3 с настройкой виртуального окружения.

#### Вариант с клонированием git-репозитория

1. Склонировать репозиторий проекта

    ```bash
    git clone https://github.com/alexander-nf/cataas-yadisk-cat-uploader.git
    ```

2. Перейти в каталог проекта

    ```bash
    cd ./cataas-yadisk-cat-uploader
    ```

3. Создать и запустить виртуальное окружение Python

    Создание виртуального окружения:
    ```bash
    python -m venv .venv
    ```

    Запуск виртуального окружения в Linux/macOS:

    ```bash
    source .venv/bin/activate
    ```

    Запуск в Windows:

    ```bash
    .venv\Scripts\activate
    ```

4. Переименовать файл `.env.example` в `.env` и задать в нём настройки программы. В частности, значения для параметров:
    - `NETOLOGY_GROUP_ID` - `"имя_учебной_группы"`, совпадающее с именем каталога хранения изображений котиков и отчёта об их загрузке;
    - `YA_DISK_TOKEN` - `"токен авторизации"`, полученный у [Яндекса](https://yandex.ru/dev/disk/poligon).

5. Создать директорию в корне своего [Яндекс.Диска](https://disk.yandex.ru) с названием `имя_учебной_группы`.

6. Установить зависимости

    ```bash
    pip install -r requirements.txt
    ```

7. Запустить приложение

    ```bash
    python ./cat_image_backup.py
    ```

### Особенности и ограничения

- Реализован не ручной ввод токена пользователем (требовалось по заданию), а ввод через `.env`-файл. Шаблон см. в [.env.example](./.env.example).
- При загрузке настроек из файла их доступность не проверяется, не установлены значения по умолчанию.
- Автоматическая фильтрация управляющих/служебных символов в тексте на картинке и названии файла происходит без уведомления пользователя.
- Невозможно сделать на картинке надпись "q".
- Автоматическая перезапись одноимённых файлов на Я.Диске происходит без уведомления пользователя и возможности отключить её.
- Использовал импорт конкретных функций: `from библиотека import метод`, для наглядности какие метода задействованы. В "долгоиграющих" проектах это может оказаться не совсем удачным решением. Так как не видна принадлежность метода библиотеке, что может запутать.

### Рефакторинг и развитие

Приложение создано:
- как для решения поставленной [задачи](https://github.com/netology-code/pyapi-diplom-basic/tree/add_cats),
- так и для демонстрации пройденных на курсе тем.

В связи с этим задача была реализована *за разумное время с разумной точностью*.

Если отталкиваться от того, что это более критичная задача/программа, а ресурсов (времени) на неё больше, вот некоторые идеи развития:
- Устранение перечня ограничений из списка ограничений выше.
- Декомпозиция классов по файлам-модулям.
- Обработка загрузки одноимённых файлов - сохранение копий / перезапись / запрос пользователя.
- Поменять цифровые коды статусов на человекочитаемые текстовые константы.
- Причесать обработку ошибок в единый стиль, систематизировать человекочитаемые сообщения логирования.
- Добавить в отчёт дату-время выгрузки изображения, другие события с внешними ресурсами.
- Замена внешнего валидатора символов `pathvalidate` на свой для надписей типа `Котология !@#$%^&*()_+`. Более точно и по ситуации фильтровать/заменять невалидные символы. Попутно убрать лишнюю зависимость/внешнюю библиотеку.
- Обработка HTTP-статусов 4xx/5xx в клиенте CatAAS и развитие обработки исключений, возможных на практике в клиенте Яндекс.Диска.
- Заменить путь к API Яндекс на имя домена без API-раздела. То есть, сделать `https://cloud-api.yandex.net` вместо `https://cloud-api.yandex.net/v1/disk/resources`. Перенастроить обработку путей API.
- Автоматизировать настройку и запуск.
- **Тесты**. Они последним пунктом = первым с конца списка, чтобы бросался в глаза. :) Тестирование проводилось, но ручным измением входных данных в настройках и коде, отключением сети, переключениями сетевой связности, копированием/удалением файлов.
